# Feedback round 30 — remove the cava FIFO input (PipeWire only)

Date: 2026-08-12 · Branch: `working` · **STATUS: IMPLEMENTED host-side
2026-08-12 (committed on `working`, 1364/1364) — do not re-implement.**

## Context

User request (2026-08-12): **remove FIFO from s2udio's cava — PipeWire
only**. The old MPD-fifo tap (setup.sh appended a fifo `audio_output` to
mpd.conf, cava read raw PCM from `/tmp/mpd-cava.fifo`, and the settings
panel offered a FIFO/PipeWire toggle) is gone; the cava visualizer now
captures PipeWire exclusively, like every other cava input the app
supported on the host.

## Change (host-implemented, round-30 commit)

1. **`src/config/cava.rs`** — the `CavaInputMethod` enum is deleted; the
   `method` field is removed from `CavaInputFile`/`CavaInput` and from
   the `cava.ron` sidecar (`CavaOverridesFile`). `to_cava_config_file`
   always writes `method = pipewire`. Legacy configs keep working: an old
   `method: Fifo` is an unknown field (ignored by serde) and a fifo
   `source` path falls back to `auto` (`sanitize_pipewire_source`, also
   applied in `CavaPane::normalize_pipewire_source`).
2. **`src/ui/modals/settings.rs`** — the "cava sample method" row
   (`GeneralRow::Method`, FIFO/PipeWire toggle) is removed; the device +
   virtual-device rows are always shown (PipeWire-only).
3. **`src/ui/panes/cava.rs`** — the MPD-fifo sample-rate/bits/channels
   sync is removed (the PipeWire input negotiates its own format); the
   sink→monitor source normalization now applies unconditionally.
4. **`src/ui/modals/paste.rs`** — `MpdFifoFormat`/`mpd_fifo_format`/
   `parse_fifo_format` (mpd.conf fifo `format` parsing) deleted.
5. **`setup.sh`** — the "MPD fifo output" step (`mpd_fifo_append`) is
   gone (steps renumbered 1/8..8/8); `assets/example_config.ron` uses
   `method: Pipewire, source: "auto"`.
6. **Container harness** — deploy scripts write a PipeWire cava config
   and no longer append the fifo output; gates G1/G4/G9 drop the fifo
   checks. G9 now asserts the deployed config is PipeWire-only and that
   cava either runs on the PipeWire input (pass — when a daemon exists)
   or fails fast with a pipewire error (soft — headless containers have
   no PipeWire daemon and several distro cavas ship without the pipewire
   input; Debian/Ubuntu cava 0.7.4, Fedora 0.10.2 built without it).
   `scripts/dev/test-setup-mock.py` arch fixture regenerated (fifo step
   removed + the round-29 shim warn the fixture was missing — mock 62/62).
7. **Harness repair (pre-existing SVP4 gap)**: the SVP4 round switched
   G1/S2 to require `input-ipc-server=/tmp/mpvsocket` in mpv.conf but no
   install path ever wrote it (the mpvSockets.lua install it replaced was
   simply removed). setup.sh's seed step, deploy-common.sh and the arch
   fixture now seed the mpv.conf line when absent (never overwriting a
   user's mpv.conf) — G1/S2 green again.

Tests: +3 (`legacy_fifo_input_falls_back_to_pipewire_auto`,
