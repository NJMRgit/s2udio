## Context

The library now ships word-timed karaoke `.lrc` sidecars (enhanced LRC,
`<mm:ss.xx>` inline word markers) generated locally with whisper — every
track gets word-per-word timing. Whisper's timestamps are close but not
perfect, and the user wants to be able to **fix timings by hand** right in
s2udio's lyrics box, and to see the exact timing of each word while doing
so.

Two pieces of feedback:

1. An **edit button** (pencil icon only, no text) on the lyrics box's
   button row, **left-aligned** on the same line as the right-aligned
   `● hide lyrics | ● fetch lyrics` cluster.
2. An **edit mode**: while it is enabled, **pausing does not hide the
   lyrics**; when paused, each word is shown **with its timing next to it
   in a different color**, and the timings can be edited.

---

## 1. Edit button — pencil icon, left-aligned on the lyrics button row

The lyrics box's bottom row currently holds the right-aligned button
cluster `● hide lyrics | ● fetch lyrics` (one cell in from the right
border). Add a **pencil icon button on the same row, aligned to the LEFT
side** of the box. **Icon only — no text label.** Suggested glyph: `✎`
(U+270E) or `✏` (U+270F), width 1.

### Requirements

- Sits on `buttons_y` (`area.bottom() - 1`), left-aligned (e.g. one cell
  in from the left border: `x = area.x + 1`).
- Toggles edit mode on click, like the other buttons (`●`/`⭘` pressed
  marker, hover highlight on the glyph only, click-zone recorded for the
  mouse handler — same conventions as `wrong_btn_area`/`fetch_btn_area`).
- When edit mode is ON, the button shows a pressed/active marker (e.g.
  `⭘` glyph or a different glyph/color) so the state is visible at a
  glance. No text.
- Must not push the right-aligned cluster off-screen: the pencil is
  independent of the cluster's fit-collapse logic.

### Implementation pointers (current code)

- `LyricsPane::render_frame` (`src/ui/panes/lyrics.rs`, round-13 layout):
  `buttons_y = area.bottom().saturating_sub(1)`; the right cluster is
  drawn from `start = area.x + area.width - cluster_w - 1`. Draw the
  pencil at `area.x + 1` on the same row, before the margin/buttons pass.
- Click zones: `wrong_btn_area`, `fetch_btn_area` fields plus the
  `LyricsBtn` enum (`Wrong`, `Fetch`) — add `LyricsBtn::Edit` and an
  `edit_btn_area`, wired through `handle_mouse_event`/`click` and the
  `pressed_btn` hover logic.
- `pressed_btn`/`glyph_of` already gives the pressed `⭘` marker pattern.

## 2. Edit mode — pause shows the lyrics with per-word timings, editable

### 2a. Pausing must not hide the lyrics while edit mode is on

Today `showing_info()` (`src/ui/panes/lyrics.rs:368`) is:

```rust
!matches!(ctx.status.state, State::Play) || self.current_lyrics.is_none()
```

i.e. pausing/stopping swaps the lyrics box to the track-details info
panel. When **edit mode is enabled**, the lyrics must stay visible while
paused (the info panel is what you get when edit mode is OFF — unchanged).
Stopped (state `Stop`) may keep showing info; the requirement is about
pause.

### 2b. Paused + edit mode: show the timing next to each word, in a different color

While paused in edit mode, every word of the current line (and ideally the
surrounding visible lines) is rendered with its timestamp displayed next
to it, e.g.:

```
word1 00:12.34 word2 00:12.62 word3 00:13.01
```

- The timing text is styled **differently from the lyrics text** — a
  distinct color (dim/secondary; e.g. reuse the theme's dim style or add a
  `lyrics.edit_timing` style to `LyricsConfig` in
  `src/config/theme/lyrics.rs`). The lyrics words themselves keep their
  normal color.
- Timings are **per-word** (the inline `<mm:ss.xx>` markers), not the
  line timestamp (the existing `lyrics.timestamp` flag shows the
  line-level `[mm:ss.xx]` — unrelated).

### 2c. The timings are editable

The user can change a word's timing while paused in edit mode. Exact
interaction is open, pick sensible defaults:

- Select a word (click it, or ←/→/w/s navigation across words) and nudge
  its time (`+`/`-` by a small step, e.g. 10 ms; shift for 100 ms), and/or
  type an exact `mm:ss.xx` value.
- Edited values must be written back to the `.lrc` file the lyrics were
  loaded from (the colocated sidecar or the `lyrics_dir` mirror — same
  file that `find_current_lyrics_path` resolved), preserving the header
  (`[ti:]`/`[ar:]`/`[al:]`), the `# lrcgen-gap-align:v1` stamp line, line
  structure, and the enhanced `<mm:ss.xx>` format; only the changed word
  markers are rewritten. Save on leaving edit mode (and/or a save key,
  e.g. `s`), and hot-reload the pane immediately.
- Note: this makes the lyrics box writable for the first time (round 23
  treats the colocated library file as read-only — edit mode is the
  explicit opt-in that writes back; the fetch hook already skips files
  with a sidecar, so it will not race the edit).

### Open questions (isodev: pick sensible defaults, flag anything ambiguous)

- Which lines show timings while paused in edit mode: only the current
  line, or all visible lines (default: all visible lines, so the user can
  fix ahead).
- Persist on every nudge vs. on leaving edit mode (default: write-back on
  leaving edit mode, plus an explicit save key, to avoid hammering the
  disk per keystroke).
- Should the nudge step be 10 ms (default) with shift=100 ms, or 50 ms?
- When playback resumes while edit mode is on, keep normal karaoke
  highlighting (default: yes — edit mode only changes the paused view and
  the button state).

## Acceptance criteria (host validates after the pull)

- Lyrics box shows a pencil icon on the bottom row, left side, same line
  as `● hide lyrics | ● fetch lyrics`; no text next to it; click toggles
  a pressed marker.
- With edit mode ON and the song paused, the lyrics stay visible (the
  info panel does not replace them); each word shows its timing in a
  different color.
- Editing a word's timing while paused updates the displayed value, and
  the change is written back to the source `.lrc` (sidecar or mirror)
  with header + `# lrcgen-gap-align:v1` stamp + enhanced format intact.
- With edit mode OFF, pausing behaves exactly as today (info panel).
- `cargo test --release` green; binary warnings ≤ 3 baseline.
