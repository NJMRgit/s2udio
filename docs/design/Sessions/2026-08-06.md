## Session 2026-08-06 (container)

Branch: `working` (tracking `origin/working`, host-pushed). Host notes in
`notes.md` at the branch tip (cbbbff1) reported: playing a YouTube audio
stream saved in a playlist shows no thumbnail, MPRIS title `index.m3u8`,
and no timeline/seek.

### Root causes found

1. **Identity loss on save.** `MpvPlaylistEntry` serialized only
   `{title,url,duration}` — the canonical YouTube link never survived
   `video-playlist.json` / `mpv-mpris.json`, and `YtStreamInfo` parsed
   yt-dlp `duration` but never stored it. The resolved HLS URL
   (`…/playlist/index.m3u8`) carries no video ID, so title + thumbnail
   lookups had nothing to resolve.
2. **Provisional-title blind spot.** `is_provisional_title` (Rust) and
   `is_provisional` (tracker) caught URL-ish titles but not bare stream
   basenames (`index.m3u8`, `audio.m4a`), so mpv's basename was pushed
   into MPRIS instead of the saved/cached title.
3. **Duration parse shift.** `read_mpv_state` collected numeric
   responses positionally — when mpv answers `duration` as unavailable
   (HLS demuxer not loaded yet), `duration` silently became the volume
   value. The tracker's index-based `value(i)` reader was already safe.

### Changes (all uncommitted; Rust needs host validation)

- `src/core/mpv.rs`:
  - `MpvPlaylistEntry.original_url` (`#[serde(default)]` — old saved
    files still deserialize) + `lookup_url()` identity helper.
  - `read_mpv_state` rewritten to per-property slot parsing; a missing
    duration can no longer shift volume/playlist fields.
  - `is_provisional_title` + new `is_stream_basename` (`.m3u8`/`.m4a`/…).
  - Restore `original_url` on session reattach.
  - Tests: duration-unavailable alignment, basename detection,
    serde round-trip + old-format default.
- `src/ui/modals/paste.rs`: populate `original_url` in the Yt→mpv entry
  paths; persist it in `save_video_playlist` + `write_mpv_mpris_state`;
  `mpv_yt_info` keys by `lookup_url()`.
- `src/core/event_loop.rs`: `MpvSessionStarted` + playlist-advance look
  up by the canonical link; the 500 ms poll only adopts mpv's title when
  it is not provisional, else falls back to cached yt-info / entry title.
- `src/shared/ytdlp/stream.rs`: `YtStreamInfo.duration` carried from
  yt-dlp (serde-compatible).
- `scripts/s2u-mpv-tracker`: `is_provisional` extended for stream
  basenames; provisional-title fallback prefers cached yt-info / playlist
  entry title; state-file playlist entries now carry `original_url`.
- `scripts/s2u-mpdris2`: new `update_metadata` patch (version-guarded,
  same pattern as `find_cover`) — injects `mpris:length` (duration) and
  `xesam:title`/`xesam:artist` for stream URLs from `yt-info.json`; MPD
  cannot report a duration for HLS, so without this the media controls
  show a dead 0-length timeline.
- `tests/tracker/test_tracker.py`: +1 unit test importing the
  working-tree script (`is_provisional` / `load_yt_info` / `_entry_title`).

- **E — mpDris2 still died 1:1 on `Seek`** (reproduced twice). Root cause:
  two shim patches were silently skipped by guards that could never be true
  against the real official mpDris2:
  1. `seekid` patch gated on `hasattr(wrapper, "seekid")` — the official

     `__getattr__` → `call()`). CommandError is caught there as `MPDError`
     → `reconnect()` → releases the D-Bus name → daemon dies. The guard was
     always False, so the official crash path ran untouched.

     dbus-python returns plain functions with `_dbus_*` attrs (no
     `.func`-wrapping Method object); guard always False.
  Fixes: install a real `seekid` class method (shadows `__getattr__`,
  catches `CommandError` → logs `Seek rejected by MPD (stream not
  seekable)` → returns False); wrap Seek/SetPosition as functions that
  copy the `_dbus_*` metadata (dbus-python `_method_lookup()` reads the
  method from the class `__dict__` per call). Verified live: Seek fwd/back
  - SetPosition all exit 0, daemon survives, journal shows the no-op log.
- **Test hermeticity / shape alignment** (`tests/mpdris_shim/`):
  1. `ART` was the real `~/.cache/rmpc/mpris-art` during tick 1 — a live
     art file made the first tick complete instead of re-arming (failed
     0/1 on this host; passed in-container only because no art file there).
     Test now points `ART` at a temp path.
  2. `FakeWrapper` defined `seekid` and the fakes used `.func` Method
     objects — neither matches the real official shapes, so the dead-code
     regressions passed. Fakes now mirror the real classes (no class-level
     `seekid`; plain functions with `_dbus_*` attrs; inner handlers raise
     the KeyError the guards must no-op).
