were wrong for v9):

1. `--http-api-listen-addr` is a **global** option (before
   `server start`) — the M1 spawn command exited 2 (`unexpected

   **no `id`/`size`**; the stream endpoint addresses files by
   **positional index**. `TorrentFileInfo` now has `name`+`length`
   (+`included`); `file_id` = index into `files`.
4. `live.download_speed` is an **object** `{mbps, human_readable}`,
   not a bare f64. New `Speed` type; M3 converts `mbps` → KB/s.
5. `DELETE /torrents/{id}` → **405**; real verb is
   `POST /torrents/{id}/delete` (files removed; `/forget` keeps
   them). `delete_torrent` switched; `api_delete` removed.

The fake-engine fixtures were updated to serve the **real v9 shapes**
(so the 6 unit tests exercise the live paths: numeric-id object,
`length`, `{mbps, human_readable}`, POST delete), plus an assertion
that the delete request is a POST. `cargo test --release` still

## Session — round 18 host validation + 4 live-check bug fixes (host, 2026-08-09)

Pulled `origin/working` (`37562d2` + `775fa4c`), re-ran the suite
(1258/1258), then live-checked the round-18 wait window with the user on a
real multi-file magnet (Banana Fish S01, 24 files). Four bugs found and
fixed host-side (all in `src/core/torrent.rs` + `src/ui/modals/paste.rs`):

1. **Cold-magnet add died at 5 s** — rqbit's `POST /torrents` blocks until
   the magnet's metainfo resolves (its handler awaits `resolve_magnet`),
   and s2udio's HTTP agent had a 5 s overall timeout, so the scan failed at
   the add step before the open-ended wait ever started. Fixed: add uses a
   1 h client timeout (`ADD_REQUEST_TIMEOUT`) and sends
   `x-req-timeout-ms: 3600000` to raise rqbit's handler cap; the add runs
   on its own sub-thread so the wait window's counter ticks and Esc cancels
   during it.
2. **Second engine failed ("rqbit api not reachable")** — rqbit `server
   start` binds a FIXED peer-listening port (4240) and a persisted DHT
   port, so a second concurrent engine (a second paste/play while the
   first engine is alive) died with "Address in use". Fixed: per-engine
   `--listen-port <free>` + `--disable-dht-persistence`.
3. **"Select files…" never played** — opening the picker is a paste-popup
   action; the popup's close hook (run right after by `MenuModal::destroy`)
   cleared `Ctx.torrent_scans`, so the picker's Enter re-lookup via
   `play_scanned_or_fresh` found nothing and fell back to the fresh
   single-file path. Fixed: the picker takes the scan out of `Ctx` when it
   opens and plays the marked files from the captured scan.
4. **Streams 500 while the engine restored the shared session** — without
   `--disable-persistence` every engine restored the shared rqbit session
   DB (60 GB of prior torrents) and checksum-validated them at startup;
   the added torrent stayed `Initializing` and rqbit's stream endpoint
   errors (`streams: invalid state`) → mpv exit 2. Fixed:
   `--disable-persistence` (clean per-engine session; s2udio manages
   torrents itself). Two follow-ups: re-added torrents whose files already
   exist in the cache need `?overwrite=true` on add (else 400 "File
   exists"), and the scan now waits for `stats/v1.state == "live"` before
   offering play (the overwrite-adopt re-checksums existing files, ~15 s
   for Banana Fish).
