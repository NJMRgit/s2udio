## Round 34 — lyrics edit mode (isodev implementation, awaiting host validation)

**User feedback → [FEEDBACK-2026-08-14-0.md](FEEDBACK-2026-08-14-0.md).**
Implemented on `working` (branch tip `a27a4c2` + this round).

### 1. Pencil button (edit-mode toggle)

- `LyricsBtn::Edit` + `edit_btn_area`, drawn on the lyrics button row
  (`buttons_y` = `area.bottom() - 1`), **left-aligned at `area.x + 1`**,
  icon only.
- Glyphs: `✎` off, `✏` while edit mode is ON (persistent active state —
  a different glyph per the feedback's open option), `⭘` while physically
  held (the standard pressed marker). Hover brightens the glyph only.
- Independent of the right-aligned `● hide lyrics | ● fetch lyrics`
  cluster's fit-collapse logic (drawn before it; survives the cluster's
  early return).
- Clicking `hide` or `fetch` while edit mode is on first leaves edit mode
  (saving) — a hidden/fetched body is contradictory with editing.

### 2. Edit mode while paused

- `showing_info()` no longer swaps to the info panel while
  `edit_mode && State::Pause && current_lyrics.is_some()`; `Stop` still
  shows the info panel (the requirement was about pause).
- The paused edit view (`render_edit_mode`) shows **every visible line**
  (anchor line at the pause position, before/after lines) with each word's
  **raw file time** next to it in a distinct style — default DIM, or the
  new `theme.lyrics.edit_timing` style (optional config). The selected
  word (and its timing) renders highlighted. Plain (non-word-timed) lines
  render normally (no per-word times, not selectable).
- Word hit areas are recorded per render (`word_areas`): clicking a word
  selects it (and focuses the pane — the lyrics pane is focusable).

### 3. Editing the timings

- **Selection**: `←`/`→` move word-to-word (wrapping across lines),
  `w`/`s` (↑/↓) move line-to-line keeping the word column (clamped).
  New default navigation bindings: `<Left>`/`<Right>` → `Left`/`Right`
  (`←` already carried `Directories(FolderCollapse)` — multi-action key
  like `w`; other panes are unaffected).
- **Nudge**: `+`/`-` nudge the selected word ±10 ms (10 ms chosen from the
  feedback's open question; `+` on the user's US layout is Shift+=, so the
  binding is `<S-+>` in config terms; the shift-for-100-ms variant has no
  distinct key on that layout — exact jumps go through the popup, and
  holding repeats via the terminal's key repeat). New actions
  `LyricsNudgeUp`/`LyricsNudgeDown`.
- **Exact value**: Enter opens an `InputModal` prefilled with the word's
  current `mm:ss.xx`; confirm parses (`mm:ss.xx` / `mm:ss:xx` / `mm:ss`),
  writes the single marker back (atomic temp+rename) and requests a
  `IndexSingleLrc` re-index, which reloads the pane in edit mode.
  Pending nudges are saved first so the popup's read-modify-write never
  races them.
- **Save**: pending edits are written back when leaving edit mode (Esc or
  the pencil) — Esc consumes the keypress so the settings panel does not
  open on the same press; `<C-s>` (`LyricsSave`) saves without leaving.
- **Write-back** (`src/shared/lrc/edit.rs`, new): the raw file text is
  kept verbatim; only the changed `<mm:ss.xx>` markers are replaced
  (interpolated words are promoted to an explicit marker on first edit).
  Header, `# lrcgen-gap-align:v1` stamp, line structure and the enhanced
  format are preserved; multiple nudges to one word save the latest time;
  save is atomic (temp + rename).
- **Lifecycle**: a song change/reconnect leaves edit mode (saving);
  `LyricsIndexed` while editing rebuilds the session in place. Resuming
  playback keeps the normal karaoke highlighting (edit mode only changes
  the paused view and the button state).

## Round 35 — line-level lyrics editing (host implementation, 2026-08-14)

**User feedback (direct to the host):** "when editing the lyrics I need
to be able to remove the lyric, edit the lyric, the timestamp, and also
add a new lyric before or after the current one" + "when edit mode is
enabled and the music is paused the selection should be on the current
lyric". Implemented host-side on `working` (round-35 commit) on top of
round 34's word editor; re-validated **1422/1422** (1408 + 9 edit.rs +
5 lyrics-pane), warnings 3 baseline, and live-checked in tmux (SGR mouse
+ raw key injection on a real whisper-generated `.lrc`).

### 1. Line-level session ops (`src/shared/lrc/edit.rs`)

- `EditableLine` now carries its **raw chunk span** (`raw_span`); the
  session keeps the original raw text and, at save, splices the output
  from the surviving lines: header/blank/metadata lines pass through
  verbatim, untouched timed lines stay verbatim (with round-34 marker-
  only word rewrites), and structurally changed lines are re-rendered
  from the model (`[mm:ss.xx]` + explicit `<mm:ss.xx>` markers). Deleted
  lines' spans are tracked (`deleted_spans`) and skipped during the gap
  fill; a `structural` flag keeps the session dirty when the last
  editable line is removed.
- `delete_line` — remove a line (pending), remapping word-edit indices.
- `set_line_text` — replace a line's words; word timings are kept
  word-for-word when the count matches, otherwise the words interpolate
  from the line time to the next line's time.
- `set_line_time` — rewrite the `[mm:ss.xx]` tag (word markers untouched).
- `insert_line_at` — insert an empty line at a position (pending).
- 9 new unit tests (spans, delete + remap, keep-times text edit,
  re-interpolation, tag rewrite, insert, combined splice preserving
  header + stamp + verbatim lines, delete-all keeps the header).

### 2. Pane wiring (`src/ui/panes/lyrics.rs`)

- New actions claimed while `edit_mode && Pause`: `d` delete current
  line (selection → next/previous line), `e` text modal (save-first +
  fresh-session apply + re-index, round-34 pattern), `i`/`a` insert
  modals (midpoint timestamp, text from the modal, re-index, the new
  line re-selected via a `pending_insert_select` flag consumed by
  `rebuild_edit_session`), `t` line-time modal.
- `UiEvent::PlaybackStateChanged` with edit mode on re-anchors the
  selection to the current lyric when paused (unless it is already on
  it), per the user's ask.
- New actions: `LyricsDeleteLine`, `LyricsEditLine`, `LyricsInsertBefore`,
  `LyricsInsertAfter`, `LyricsLineTime` (defaults, example_config.ron,
  remap display names, no-op arms in song_list/search; live config.ron
  updated host-side). 5 new pane tests.
- Docs: interaction.md (line-editing section), this session log,
  notes.md.

### Live validation (round-35 build, tmux + SGR/key injection)

## Round 38 — lyrics source priority option + Esc-in-edit-mode regression fix (2026-08-14)

**User feedback → [FEEDBACK-2026-08-14-1.md](FEEDBACK-2026-08-14-1.md).**
Implemented in the container on `working`: **1434/1434**, warnings 3
baseline.

### 1. `lyrics_source` config option (local-first default / local-only)

- New enum `LyricsSource { LocalFirst (default), LocalOnly }`
  (`src/config/cli.rs`, re-exported from `src/config/mod.rs`) —
  `ConfigFile.lyrics_source` (serde RON key, PascalCase variants,
  `ShowPlaylistsMode` style) flowing through `into_config` into the
  runtime `Config`.
- New CLI flag `--lyrics-source <local-first|local-only>` (clap
  kebab-case), applied as an override in `read_config_and_theme` and the
  `Config::default_cli` fallback; absent flag = config file/default wins.
- `assets/example_config.ron` documents the key (commented
  `lyrics_source: LocalFirst`) — `s2udio config` prints it as well.
- `LocalOnly` never spawns the network fetch: both `on_song_change`
  execution sites in `src/core/event_loop.rs` (startup
  `exec_on_song_change_at_start` and the on-song-change handler) skip
  the hook entirely. Sidecar → mirror → index resolution in
  `find_current_lyrics_path` is untouched; the manual "fetch lyrics"
  button still works (user-initiated, per the feedback's open-question
  default).

### 2. Esc-in-edit-mode regression (opened Settings instead of discarding)

- Root cause: `LyricsPane::handle_action` claimed the edit key set only
  while paused, but the pencil toggles edit mode in any play state — Esc
  while playing therefore fell through to the global `ShowSettings` half.
- Fix: while edit mode is on (session open) Esc (`Close` = discard),
  `<C-c>` (`LyricsSaveAndExit` = save+exit) and `<C-s>` (`LyricsSave` =
  save in place) work in **any** play state and consume the key; the
  remaining edit keys stay paused-gated and are abandoned (fall through
  to the global handlers) while playing. `handle_action` only runs for
  the focused pane, so this is pane-scoped by construction.
- Tests: `esc_while_playing_exits_edit_mode_without_opening_settings`,
  `ctrl_c_saves_and_exits_while_playing`,
  `edit_mode_playing_does_not_claim_non_exit_keys`; config tests
  `lyrics_source_defaults_to_local_first`,
  `lyrics_source_parses_from_ron`, `lyrics_source_flows_through_into_config`,
  `config::cli::tests::lyrics_source_cli_flag_parses`.

## Round 39 — per-word insert (i/a split at the word) + add-line option (o/O) (2026-08-14)

**User (direct to the host):** "inserting a lyric before or after inserts
on the LINE before or after instead of the WORD before or after. add an
option to add a new line and ensure the inserts are per word not line".

Implemented host-side on `working` (on top of round 38): **1442/1442**,
warnings 3 baseline.

### 1. `i`/`a` split the line at the selected WORD

- `LrcEditSession::split_line_at_word(line, word, after)` — the words
  after the split point move to a new `EditableLine` (raw_span None,
  dirty) whose tag is the moved word's time (`i`: the selected word's
  time, split before it; `a`: the next word's time, split after it). The
  original line keeps the earlier words, its `content` rebuilt from the
  remaining words, and is marked dirty so `save` re-renders both halves
  with explicit markers (moved words keep their exact timings). Pending
  word edits remap with the moved words; line indices after the insert
  shift. Errors on line edges/wordless lines (caller falls back to the
  add-line modal).
- `render_pending` now buffers inserted (no-raw-span) lines and emits
  them right after the preceding raw gap — a line split before the FIRST
  lyric previously rendered in front of the header/metadata.
- `LyricsPane::split_at_selected_word`: save-first, fresh session, split,
  save, `IndexSingleLrc`, `pending_insert_select` → the new line is
  re-selected. Edge cases fall back to `insert_new_line` (the modal).

### 2. New add-line option

- `o` = `LyricsAddLineAfter`, `O` = `LyricsAddLineBefore` — the old
  whole-line insert (midpoint timestamp + text modal). New actions
  (CommonAction + CommonActionFile serde names), default navigation
  bindings, descriptions, reverse remap, remap-keys display names, no-op
  arms in song_list/search, example_config.ron + live config.ron.
- Legend: `i / a split at word`, `o / O add line`.

### Live validation (isolated MPD on :6601, scratch .lrc copy)

- i on "dream" (selected at the pause position) → `[00:13.00]dream` new
  line, "I still feel your touch in my" kept on `[00:08.20]`; header +

- a on "I" → `[00:01.45]I` kept, rest moved to `[00:02.63]still … me`;
  selection lands on the new line.
- i on a line's first word → "New lyric before" modal (fallback);
  o → "New lyric after" modal; O → "New lyric before" modal.
- Legend shown in edit mode (window ≥ 57 rows): `i / a split at word`,

## Round 40 — i/a insert a WORD into the same line + legend survives modals (2026-08-15)

**User (direct to the host, on round 39):** "the legend disappears if I
add a word. also adding a word before the first word of the line makes a
new line before it instead of appending it to the current line. I want to
add words to the SAME line".

Implemented host-side on `working`: **1442/1442**, warnings 3 baseline.

### 1. i/a = in-line word insert (round 39's split replaced)

- `LrcEditSession::insert_word_at(line, word, after, text)` — the new
  `EditableWord` (marker None) is inserted into the line's words at the
  selected word's position; time = midpoint between the neighbours
  (previous word / line timestamp at the start; next word / next line
  timestamp / prev+5 s at the end). The line is marked dirty → save
  re-renders it with explicit markers; pending word edits after the
  insertion shift by one.
- `LyricsPane::insert_word` — save-first, fresh session, modal
  ("New word before/after", "Word:" label), confirm writes via
  `insert_word_at` + save + `IndexSingleLrc`; `pending_insert_select`
  became `(line, word)` so the reload selects the inserted WORD.
- `o`/`O` keep the whole-line add. The round-39 split op was removed
  with its tests; `render_pending`'s inserted-line buffering stays (it
  also fixes `O` before the first lyric line placing the new line after
  the header).

### 2. Legend fix (modal wipe)

- `CavaPane::on_event(ModalOpened)`: skip `pause_and_clear` while
  `ctx.lyrics_edit_mode` is set. The direct terminal write was wiping
  the buffer-resident legend; the buffer was never invalidated, so the
  legend stayed invisible until a full re-render (resize). With the
  guard, the modal paints over the legend and closing it restores it.
