### What changed (one commit on `working`)

- **Config** (`src/config/tabs.rs`, `src/config/mod.rs`): the default
  tabs drop the `Search` TabFile (tab bar → `Queue │ Playlists │ MPD •
  Jellyfin • Radio`); `is_tab_hidden` now also hides any leftover tab
  literally named `Search`, so no config can resurrect it in the bar or
  the tab cycle (a stale `state.ron` `last_tab = "Search"` falls back to

- **MPD pane** (`src/ui/panes/directories.rs`): `MpdTabMode`
  {Library, Search}; a `⭘ Library  ● Search` toggle row renders at the
  top of the pane (reuses the queue's `SubTabBar` widget — ● active +
  bold, ⭘ inactive + dim, hover-lightens, one leading space, click
  areas stored for mouse routing). Library mode = the unchanged
  tree-browser render (min-50/hide-≤120 tree, Esc-deselect etc.);
  Search mode = an embedded `SearchPane` (`search: SearchPane`,
  session-lifetime so filters/results survive toggles; mode resets to
  Library at startup). `handle_action` claims the `NextTab` global
  (`Tab`) and toggles the mode instead of cycling tabs — **only while
  the MPD tab is focused** (`E` and Shift+Tab still cycle tabs
  everywhere). Mouse clicks on the toggle labels switch modes; Esc with
  a search selection still clears the marks through the embedded pane.
  `on_event` now forwards every event to the embedded search (Database /
  Reconnected / ConfigChanged parity with the old standalone tab);
  `on_query_finished` forwards everything that is not a tree/play-file
  result to it.
- **Query routing** (`src/ui/panes/search/mod.rs`): the search's two
  queries target `PaneType::Directories` now (was `PaneType::Search`),
  so results reach the MPD pane, which forwards the `SEARCH` id to its
  embedded search. The `SEARCH` id const became `pub(crate)`. Added a
  `#[cfg(test)]` buffer-id accessor on `SearchPane` to pin the
  filter-survival test.
- **Tests**: +6 MPD-tab tests (toggle row marks the active mode and
  Library default; label clicks switch modes; `Tab` toggles; Search mode
  renders the folded-in UI and receives results; filters survive
  Library↔Search; Esc clears search marks + consumes) + 1 tab-bar test

## Round 28b — Shift+Tab toggles Library/Search (host live-check fix, 2026-08-12)

Host live-check feedback on the round-28 toggle: it captured `Tab` (and
`E`, both `NextTab`), so from the MPD tab neither key cycled tabs — the
tab was effectively keyboard-unreachable (`Q` was the only way out).
The user's correction: **ONLY `Shift+Tab` should switch Library/Search**;
`Tab` / `E` / `Q` must keep cycling tabs. Host-implemented on `working`
as the round-28b commit (the round-13 precedent: host implements small
live-check fixes directly).

### What changed (one commit on `working`)

- **New global action `ToggleMpdMode`** (`src/config/keys/actions.rs`:
  enum + file enum + both conversions + `ToDescription`), bound by
  default to `Shift+Tab` (`keys/mod.rs` default global table;
  `assets/example_config.ron`; the live `~/.config/s2udio/config.ron`
  global table too, since the user's `keybinds: clear: true` replaces
  defaults). Added to the `steps_once` single-step set
  (`shared/keys/actions.rs`), to the global executor as a no-op outside
  the MPD tab (`ui/mod.rs`), and to the remap UI description
  (`modals/remap_keys.rs`).
- **`DirectoriesPane::handle_action`** (`src/ui/panes/directories.rs`):
  claims `GlobalAction::ToggleMpdMode` (and ONLY it) while the MPD tab
  is focused → `toggle_mode()`. The round-28 `NextTab` claim is removed,
  so `Tab` / `E` (NextTab) and `Q` (PreviousTab) fall through to the
  global handler and cycle tabs as before — the MPD tab is always
  reachable/leavable from the keyboard.
- **No behavior change anywhere else**: `Shift+Tab` resolves to
  `Queue(ToggleChapters) + Global(ToggleMpdMode)` for one press; the
  queue pane claims the queue half first (so its chapters toggle keeps
  working), and in every other tab `ToggleMpdMode` is unclaimed → the
  executor's no-op arm.
