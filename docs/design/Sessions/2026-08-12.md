## Round 30 — remove the cava FIFO input, PipeWire only (host-implemented, 2026-08-12)

User request: **remove FIFO from s2udio's cava — PipeWire only**. The
cava pane previously had two input paths: an MPD fifo tap (setup.sh /
deploy scripts appended a fifo `audio_output` to mpd.conf, cava read raw
PCM from `/tmp/mpd-cava.fifo`, and the settings panel exposed a
FIFO/PipeWire "cava sample method" toggle) and PipeWire. Only PipeWire
remains.

### What changed (one commit on `working`)

- **Config** (`src/config/cava.rs`): `CavaInputMethod` enum deleted; the
  `method` field is gone from `CavaInputFile`/`CavaInput` and from the
  `cava.ron` sidecar (`CavaOverridesFile`). `to_cava_config_file` always
  writes `method = pipewire`. Migration: a legacy `method: Fifo` is an
  unknown field (serde ignores it) and a fifo `source` path falls back
  to `auto` (`sanitize_pipewire_source`, used in `From<CavaFile>` and
  `CavaOverridesFile::apply_to`; `CavaPane::normalize_pipewire_source`
  does the same at spawn time).
- **Settings** (`src/ui/modals/settings.rs`): the FIFO/PipeWire method
  row (`GeneralRow::Method`) and `StagedCava.method` are removed; the
  device + virtual-device rows are always shown (PipeWire-only).
- **Spawn** (`src/ui/panes/cava.rs`): the MPD-fifo sample
  rate/bits/channels sync is deleted; the sink→monitor source
  normalization is unconditional.
- **`paste.rs`**: `MpdFifoFormat`/`mpd_fifo_format`/
  `parse_fifo_format` (mpd.conf fifo `format` parsing) deleted.
- **Setup** (`setup.sh`): the MPD fifo output step is removed (steps
  renumbered 1/8..8/8); `assets/example_config.ron` → `method:
  Pipewire, source: "auto"`.
- **Container harness**: deploy scripts write a PipeWire cava config and
  no fifo output; gates G1/G4/G9 drop the fifo requirements — G9 now
  asserts the deployed config is PipeWire-only and cava either runs on
  the PipeWire input or fails fast with a pipewire error (headless
  containers have no PipeWire daemon; Debian/Ubuntu cava 0.7.4 and
  Fedora 0.10.2 ship without the pipewire input). The
  `setup.sh.arch-baseline` fixture was regenerated (fifo step removed +
  the round-29 shim warn it was missing) — mock 62/62.
- Docs: `backend/mpd-playback` (fifo tap → PipeWire capture),
  `config-sidecars`, `image-overlays`, `Tabs/settings`, README, HANDOFF,
  distro-support plan.
- **Harness repair (pre-existing SVP4 gap)**: G1/S2 wanted
  `input-ipc-server=/tmp/mpvsocket` in mpv.conf but nothing wrote it
  (SVP4 replaced the mpvSockets.lua install with the check without
  seeding the file). setup.sh's seed step, deploy-common.sh and the arch
  fixture now seed the line when absent.

## Round 29 — name the cava PipeWire node (host-implemented, 2026-08-12)

User request: name the cava node s2udio uses. Investigation first
(`input/pipewire.c` @ 0.10.7 + master): cava hardcodes
`pw_stream_new_simple(loop, "cava", props, ...)` — `node.name` and
`media.name` become "cava" via libpipewire's `stream_new`; no cava
config/env option exists; WirePlumber 0.5 cannot rename an app-set
`node.name` from outside (its old `nickname` settings-metadata rename is
not implemented in this install — verified empirically). A minimal
LD_PRELOAD shim that injects `node.name`/`media.name` from an env var
was proven live before implementing.

### What changed (one commit on `working`)

- **Config** (`src/config/cava.rs`): `CavaInput.node_name:
  Option<String>` (+ `CavaInputFile.node_name`, serde-default) and
  `CavaOverridesFile.node_name` (`Some(name)` renames, `Some("")`
  disables, `None` untouched). Settings panel
  (`src/ui/modals/settings.rs`) carries it through `StagedCava` so a
  Save never drops it.
- **Shim** `scripts/cava-node-name.c` (new): LD_PRELOAD override of
  `pw_stream_new_simple` setting `node.name`/`media.name` from
  `CAVA_NODE_NAME` (transparent pass-through when unset). `setup.sh`
  builds it into `~/.local/share/s2udio/libcavaname.so`
  (`install_cava_name_shim`, non-fatal without a C compiler);
  `shared::paths::cava_node_name_shim()` resolves it
  (`S2UDIO_CAVA_NAME_SHIM` override).
- **Spawn** (`src/ui/panes/cava.rs`): when `node_name` is configured,
  spawn cava with `LD_PRELOAD=<shim> CAVA_NODE_NAME=<name>`; a missing
  shim logs a warning and cava runs with its own name.
- Example config + docs (`config-sidecars`, `image-overlays`).

### Tests

+3: `node_name_override_sets_and_disables`,
`main_config_input_parses_node_name`,
`node_name_rename_env_filters_empty_names` — **1364/1364**, warnings 3

### Live check (2026-08-12)

## Round 31 — multi-select: Ctrl+A, additive ctrl+click, bulk actions (host, 2026-08-12)

User feedback
([FEEDBACK-2026-08-12-4.md](FEEDBACK-2026-08-12-4.md)):
(1) **Ctrl+A** selects all items of the current pane (Queue /
Playlists / MPD; not Jellyfin / Radio / Help / Settings / the MPD
search filter pane); (2) **ctrl+click** must ADD to the initially
selected item (it currently deselects it); (3) multi-selection gains
bulk actions in the queue / library / search results, add/create
playlist uses exactly the selected tracks, plus *Add queue to playlist*
and *Create playlist from queue*.

### What changed (one commit on `working`)

- **New `CommonAction::SelectAll`** (`src/config/keys/actions.rs` +
  remap-keys description), bound to **`<C-a>`** in the navigation
  defaults (`src/config/keys/mod.rs`), `assets/example_config.ron` and
  the live `~/.config/s2udio/config.ron` (the host config has
  `keybinds.clear: true`, so the live file needs the entry too). Parsed
  as `Char('a') + CONTROL` — exactly what crossterm reports for Ctrl+A;
  insert mode (filter typing) never fires it.
- **Handlers**: `SongListCore::handle_claimed_common_action` (queue
  audio list, playlists songs, search results), `queue/video.rs`
  (video list), `tree_browser.rs` via a new `on_select_all` trait hook
  overridden in `DirectoriesPane` (MPD right pane). PlaylistsPane
  intercepts SelectAll and applies it only inside a playlist (the root
  playlist list is a no-op); SearchPane no-ops it in the filter phase
  (results phase routes to SongListCore). Second Ctrl+A keeps
  everything marked; Esc clears.
- **Ctrl+click is now additive** in all five multi-select lists (queue
  audio `queue.rs`, queue video `queue.rs`, MPD right pane
  `directories.rs`, playlists songs, search results): when no rows are
  marked the row under the cursor joins the marks (the initially
  selected item is never dropped), and the clicked row is added without
  toggling off — clicking an already-marked row keeps it. Plain click on
  another row / Esc still clear. `MarkState::toggle` is gone (replaced
  by `MarkState::add` + `mark_all`).
- **Bulk actions**:
  - *Playlists songs menu* (`playlists.rs open_song_menu`): acts on
    every marked song (else the highlighted one) — Add to queue /
    Replace queue / Create playlist / Add to playlist / **Remove from
    playlist** (the last two and the removal were single-song before).
  - *Search results menu* (`search/mod.rs`): marked/selected results
    now get **Add to queue** and **Replace queue** (the "all" variants
    stay).
  - *Audio queue menu* (`queue/context_menus.rs`): with marks active,
    **Add selected to playlist** and **Create playlist from selected**
    (only the marked rows land in the playlist); *Create audio
    playlist* renamed **Create playlist from queue** (whole queue, next
    to the existing *Add queue to playlist*).
- **Docs**: interaction.md (multi-select + Ctrl+A), queue-tab.md /
  mpd-tab.md / playlists-tab.md / search-tab.md, HANDOFF, notes.md.
