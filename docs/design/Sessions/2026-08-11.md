**Design notes / gotchas hit:**

- **Submodule visibility**: private inherent methods defined in a child
  module are *not* visible from the parent module, so method resolution
  at queue.rs call sites silently fell back to the `SongListCore` trait's
  `open_context_menu` default (`Result<()>`) and broke the
  `handle_video_action` match-arm types. Fix: the moved functions are
  declared `pub(super)` (identical effective visibility to their
  original private-in-`queue` declarations, which already covered
  `queue` + its test mods). Same pattern as `search/inputs.rs`'s
  `pub(super)` items.
- **Metrics trap confirmed**: `ui-metrics.py` reads the file list from
  `git ls-tree HEAD` but contents from the worktree without `--ref`, so
  the new submodule files are silently excluded from pre-commit runs —
  all 4b numbers were measured on committed refs.
- **Stays put by design**: `current_chapters`/`chapters_available`
  (used by dispatchers/toggle too), all struct fields, the `SongListCore`
  impl, and all five `#[cfg(test)]` mods (1775 test LOC byte-identical).

**Numbers** (committed refs, `python3 scripts/dev/ui-metrics.py --ref`):
queue.rs **4447 → 3485** (production 2673 → 1711, **−962**; tests 1775 →
1775); new submodules 347 + 373 + 325; src/ui 56,987 → 57,070 (+83);
tree 96,045 → 96,128 (+83) — a pure-move split is LOC-neutral by design
(the headers/imports cost ~28 lines/file); the −950 production-LOC
target is met. Similarity guardrail: **60 excl-thin pairs, identical
pair set** before/after (moved fns keep unique names → no new pairs).

**Remaining**: the phase-4 host live-check (plan §8 — Audio/Video/

## Phase 6 — args expansion (devcontainer, 2026-08-11)

Executed the Phase 6 handoff plan
(`docs/design/Rewrite/phase6-args-expansion.md`) on branch `rewrite`
(working tree was clean at `5a2ce9d`): moved the pane-specific browser
constants (tree min-width 50 / hide threshold 120 / info-box cap 15)
into `PaneType`/config args with serde defaults, wired them through the
browser family, and closed the phase with a documented construction
pattern. Four commits, each independently green (1337/1337 at the close,
warnings 3 baseline, similarity guardrail 60 excl-thin with an identical
pair set before/after):

- **6.1 (`4a5b054`)** — `TreeBrowserArgs` (`tree_min_width` 50,
  `tree_hide_below` 120, `info_box_cap` Some(15)) + the four variant
  fields on both `PaneTypeFile` and `PaneType`; TryFrom + every
  exhaustive match fixed (`{ .. }` where fields are irrelevant, args
  carried at construction). **Backward compatibility was NOT free**: RON
  cannot deserialize a struct variant from its unit form, so
  `#[serde(default)]` alone breaks today's bare `Directories` syntax.
  `PaneTypeFile`'s `Deserialize` is now manual: capture with serde's
  `Content` (the versioned `__private228` hidden module, pinned by the
  lockfile), dispatch bare unit names with default args, rewrite
  `{Variant: ()}` → `{Variant: Seq([])}` (RON encodes every
  parenthesized variant as a map; serde's tuple-variant replay needs a
  sequence), replay into a derived mirror enum, convert. Pinned by
  `bare_browser_panes_parse_with_default_tree_args` +
  `explicit_tree_args_round_trip` + `default_args_are_today_s_constants`;
  the example config/theme (bare `Pane(Radio)`, `Pane(Empty())`,
  `Property(Status(InputBuffer()))` …) parse unchanged. 1331/1331.
- **6.2 (`a1caf6b`)** — `TreeBrowserArgs::tree_width`/`info_box_height`
  (defaults = today's `tree_width()` / `.min(15)`),
  `Config::tree_browser_args` (first config occurrence drives the
  singleton pane), a `tree_args` hook on `TreeBrowserCore` feeding the
  shared `split_tree`; directories/playlists/jellyfin/radio read the args
  (radio keeps its always-visible 30% regions tree — its shape). The
  tree-width + info-box-cap parity tests stay green UNCHANGED; one new
  test per pane (radio's documents the arg-independent shape). 1336/1336.
- **6.3 (`9abb201`)** — construction pattern: **documented decision**.
  Recipe doc `docs/design/Rewrite/new-browser-tab.md` — a new browser
  tab = config block (a `PaneType` variant carrying `tree: TreeBrowserArgs`)
  + a thin adapter over the shared cores, never a new core implementation
  (precedent: `PaneType::Browser` + `TagBrowserPane`). Unifying the four
  panes into one config-driven backend enum was attempted and rejected
  (Phase-5 §3 rule): it would change observable behavior in four pinned
  places — radio's focus-aware back-out + always-visible regions tree,
  jellyfin's shared selection + poster overlay + season expansion,
  playlists' list-shaped left pane (`BrowserPane`, ♪/▶ prefixes),
  directories' disk-backed Downloads folder — a fork, not an arg. Plus a
  config→args bridge test. `tree_args` added to the metrics script's
  thin-adapter list. 1337/1337.
- **6.4 (close-out)** — docs + metrics (this entry, outline §2.4/phase
  row/§5.5, HANDOFF, plan flipped done, `new-browser-tab.md` registered
  in the design index).

**Real numbers (ref-to-ref `5a2ce9d` → HEAD)**: src/ui 57,173 → 57,318
(+145), tree total .rs 96,231 → 96,797 (+566; the manual serde machinery
