### Validation of round 32 (`9b1122a`, pulled from ~/Projects/s2udio)

- **1385/1385** tests green, warnings 3 baseline; binary installed + live-checked
  in a tmux session (mouse events injected as SGR wheel sequences).
- Wheel viewport-scroll verified live in Queue (audio), Playlists, MPD
  (tree), Radio (regions); Info boxes keep content scroll; **Settings keeps
  wheel-moves-selection**; **Jellyfin keeps wheel-moves-selection**
  (`TreeBrowserCore::wheel_scrolls_viewport()` = false) — all as specced.
- Three failures found live (the unit suite did not cover them):

1. **Queue wheel could not scroll the viewport past the selection**
   (user-reported). `VirtualizedTable::render` restored the state through
   `DirState::select(sel, 0)`, which re-applies the scrolloff clamp: every
   render after a viewport-only wheel scroll pulled the offset back the
   moment the highlight hit the top (or bottom) row. The round-32 wheel
   tests never rendered between events, so they missed it (production
   renders after every wheel event). **Fix**: restore the raw selection +
   scrollbar without the clamp (`inner.select_scrolling` +
   `scrollbar_state.position`). Regression test
   `wheel_scrolls_the_viewport_past_the_selection_with_renders_between`
   (renders between events; fails on the old code).
2. **Startup jump re-centered**: the one-shot `select_at_top(playing_idx)`
   ran, then a second `before_show` (startup tab init) hit the re-show
   branch, which re-selected with `usize::MAX` (center) — a fresh start
   showed the playing track CENTERED, not as the first visible row.
3. **Tab switch re-centered**: the same re-show branch re-centered on EVERY
   tab switch back, discarding the wheel scroll position.

   **Fix (2+3)**: the re-show branch now keeps the user's selection AND
   scroll position (only re-lands when the selection fell out of bounds,
   e.g. after a queue reload). `first_show_jumps_to_the_playing_song_at_the_top`
   strengthened to assert the offset is preserved on re-show.

- Re-validated: **1386/1386** (+1 regression test), warnings 3 baseline.
  Live: fresh start = playing track as first visible row; wheel scrolls the
  full list in both directions with the highlight leaving the window;
  keyboard moves still scroll the selection back into view; tab switches
  preserve selection + scroll. Binary installed + running.
