## Context

User request (2026-08-12): the **Search tab currently only searches the
user's MPD library**, so it is not a first-class source on par with
Jellyfin/Radio — it belongs *inside* the MPD tab. Change: **fold the
Search tab into the MPD tab** with a toggle inside the MPD tab that
switches between **Library** and **Search**. The top-level Search tab
goes away entirely (the tab bar returns to `Queue │ Playlists │ MPD •
Jellyfin • Radio`); the search UI moves into the MPD tab as its
"Search" mode. Do not change what each mode searches — Search still
searches the user's MPD library, it is just no longer a separate tab.

## Change

1. **Remove the top-level Search tab** — the tab bar renders
   `Queue │ Playlists │ MPD • Jellyfin • Radio` (no Search entry).
2. **Add a Library/Search toggle inside the MPD tab**, rendered as a
   `⭘ Library  ● Search` row immediately below the tab bar (left-aligned,
   one leading space, exactly as drawn). The active mode uses **●** and
   the inactive one **⭘** (the app's existing ●/⭘ marker convention).
   - **Mouse**: clicking "Library" / "Search" on the toggle switches modes.
   - **Keyboard**: a binding to switch modes — TBD, must not collide with
     the MPD tab's existing `a`/`d`/`←`/`→` pane navigation; leading
     suggestion is `Tab` while focused in the MPD tab (confirm with the
     user if in doubt).
3. **Library mode = the current MPD tab, unchanged** — Folders left pane +
   Library(N) items right pane + info + footer (`w/s · ↑/↓ folders ·
   items`, `d / a open · back out`, `Enter context menu`), including the
   existing left-pane min-width-50 / hide-when-TUI-≤120-cols behavior and
   multi-select (incl. the round-24 Esc-deselect).
4. **Search mode = the current Search tab UI, moved in** — Search filters
   left pane + Results right pane + info + footer (`w/s · ↑/↓ filters ·
   results`, `Enter options menu · d/→ play`, `Shift+↑/↓ multi-select
   results`), with **all** rounds 24–27 search behavior intact: mouse
   multi-select (ctrl/alt/plain click), marked-row + hover rendering,
   dual-pane `a`/`d`/`←`/`→` filter↔results navigation, adaptive filter
   labels (round 26), aligned label spacing + Enter/Space options menu +
   Play item (round 27), Esc-deselect. Searches still query the user's
   MPD library.

## Open questions (isodev: pick sensible defaults, flag anything ambiguous)

- Default mode at startup: **Library**.
- Keyboard toggle binding: pick one that doesn't collide (see §Change.2);
  `Tab` within the MPD tab is the leading suggestion.
- Is the selected mode remembered across restarts (state.ron) or reset to
  Library each launch? Default: reset to Library; note in the PR if
  persisting it is trivial.
- Are the search filters preserved when toggling Library↔Search within a
  session? Default: yes — the search state object lives for the session.
