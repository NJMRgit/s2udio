# Feedback round 38 — lyrics source priority option: local .lrc first, other sources as fallback

Date: 2026-08-14 · Branch: `working` · **STATUS: OPEN — feedback filed for isodev**

## Context

The music library now ships word-timed karaoke `.lrc` sidecars (enhanced
LRC, `<mm:ss.xx>` inline markers) generated locally with whisper —
10,5xx of 11,954 tracks. The user wants s2udio to **explicitly prioritize
these local `.lrc` files and treat every other source as a fallback**,
controlled by a config option.

Today the lookup order is hardcoded (round 23 comment in
`Ctx::find_current_lyrics_path`, `src/ctx.rs`): 1. colocated sidecar in the
MPD library (read-only), 2. `lyrics_dir` mirror, 3. the lyrics index, and
network fetch as a last resort via the `on_song_change` hook
(`rmpc-fetch-lyrics`), which is already skipped when a sidecar exists
(`HAS_LRC=true` guard). That is effectively "local first with fallbacks",
but there is **no option** to select it, document it, or turn the network
fallback off. This round adds that option.

---

## 1. New config option: lyrics source priority

Add a config option (suggested name `lyrics_source`, an enum; isodev may
pick a better name, keep it consistent with the existing config style in
`src/config/mod.rs`):

- **`local-first`** (default) — current behavior, made explicit:
  1. colocated `.lrc` sidecar (MPD library, read-only)
  2. `lyrics_dir` mirror (`get_lrc_path`)
  3. lyrics index (metadata match)
  4. network fetch (`on_song_change` → `rmpc-fetch-lyrics`) as the last
     fallback, still gated by the existing `HAS_LRC` guard.
- **`local-only`** — steps 1–3 exactly as above, **no network fetch at
  all**: lyrics only ever come from local files. The `on_song_change`
  hook must not spawn the fetch command.
- Enum is extensible; no other modes needed today (a `fetch-first` /
  mirror-over-sidecar mode is explicitly NOT wanted).

### Requirements

- Default `local-first` must reproduce today's behavior exactly.
- Plumbing: serde config field + CLI arg + RON key (follow the existing
  `enable_lyrics_index` / `enable_lyrics_hot_reload` pattern), default
  value, and a one-line mention in the config docs/example.
- The lookup order in `find_current_lyrics_path` stays as-is (sidecar
  first); the option's job is to make that explicit and to gate the
  network fallback. No changes to the mirror/index resolution.

### Fetch gating (local-only)

- `core/event_loop.rs`: the `on_song_change` execution at startup
  (~line 200, `exec_on_song_change_at_start`) and on song change
  (~line 1736) must **not run the command** when `lyrics_source =
  local-only`. Don't spawn it, don't pass env tricks — just skip.
- When `local-only`, the manual "fetch lyrics" button
  (`LyricsPane::fetch_lyrics`) may still work (user-initiated, explicit
  action) — see open question.

### Implementation pointers (current code)

- `src/config/mod.rs` — `Config` struct (~line 52, 113-117) + `ConfigFile`
  serde section (~line 228-231) + `Default` (~line 310) + the merge into
  `Config` (~line 497-503).
- `src/core/event_loop.rs` ~lines 198-206 and ~1733-1750 — the two
  `on_song_change` execution sites.
- `src/ctx.rs` `find_current_lyrics_path` (~line 669) — reference only;
  the option does not change this order.
- `create_env` (`src/core/command.rs`) already exports `HAS_LRC` /
  `LRC_FILE` — unchanged.

### Open questions (isodev: pick sensible defaults, flag anything ambiguous)

- In `local-only` mode, should the manual "fetch lyrics" button be
  disabled/hidden, or still work as an explicit user action? Default:
  still works (auto-fetch gated, manual allowed).
- Naming: `lyrics_source` vs `lyrics_priority` vs a boolean
  `lyrics_fetch_enabled`. Default: enum `lyrics_source` (extensible).

## Acceptance criteria (host validates after the pull)

- `lyrics_source` config option exists with default `local-first`; RON +
  CLI accept it; docs/example mention it.
- Default (`local-first`): behavior identical to today — sidecar wins,
  then mirror, then index, then fetch (fetch skipped when `HAS_LRC`).
- `local-only`: sidecar/mirror/index all still resolve; the fetch command
  is **not** spawned on startup or song change (verify with `ps`/logs);
  songs with sidecars and songs with only mirror/index lyrics both display
  correctly.
- `cargo test --release` green; binary warnings ≤ 3 baseline.
